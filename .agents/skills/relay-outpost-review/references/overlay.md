# Relay Outpost overlay (R1–R12) — for code-architect threshold mode

Applies on top of code-architect's universal core (C1–C8) and its security rows (S1–S4) to any change in this repo. These are the bars that have actually bitten us; each row names where the rule came from. **Fail** rows are mandatory. **Flag** rows are questions for the author. The Rise overlay (O1–O4) is always n/a here.

Report shape is the same contract: one line per row, the ID first, then pass / flag / fail / n/a, then the reason (the smallest correction for a fail; the question for a flag).

| ID | Checks | Fail when | Smallest correction | Where it came from |
|---|---|---|---|---|
| **R1 — Three outcomes, not two** | A relay fetch can end with data, genuinely empty, or *we never got to ask*. Code that shows "nothing here" must have a positive signal that the question was answered. | An empty result is rendered as an empty state (or a count of 0) with no `answered` / `reached` signal distinguishing it from "no relay answered". | Use `queryAnswered` / `withReach` (`client/src/lib/relay-reach.ts`) and render the unreachable case as its own state. | `RELAY_REACHABILITY.md`; three shipped "No X yet" screens over offline relays. |
| **R2 — EOSE is not reachability** | nostr-tools fires `oneose` when a relay *fails* to connect, and invents one on a timeout. | `oneose` (or a `[]` resolved on it) is treated as "the relay answered" or "connected". | Gate on `pool.ensureRelay` / `onrelayeose` (a relay's own EOSE) / `queryAnswered`; never on the invented one. | `fabricated-eose-not-an-answer`, `relay-declines-are-not-crashes`. |
| **R3 — One word per thing** | User-visible strings use the words in `VOCABULARY.md`; a retired word never reaches a screen, and an existing thing never gets a second name. | A retired word (broadcast, transmit, signal, crew, orbit, station, mission, Outpost-as-a-thing, secret key / nsec, passphrase, DM, hangout, channel-for-room, Alerts/Notifications-as-a-place, WoT, Shield Matrix…) in JSX text or a quoted sentence. | Use the word the table gives; explain it once on first appearance. | `VOCABULARY.md`, `client/src/vocabulary.test.ts`. **Flag** a new name for something that already has one. |
| **R4 — Status words, not pills; legible** | Status is a plain coloured word ("3 new", "Live"), not a badge; green is `text-success`; muted grey never below `/60`; no new text under 10px. | A status rendered as a pill/badge; `text-green-*` for a status; `text-muted-foreground/40`-style greys for words people must read; `text-[8px]`/`text-[9px]`. | Plain word with `text-success` / `text-muted-foreground/60`+; 10px minimum. | `status-words-not-pills`, the legibility ratchet, `enterprise-look-plain-words`. |
| **R5 — Violet is for actions** | The brand violet marks actions, focus and selection only; light-mode work never changes dark mode. | Violet on decorative or informational text; a light-mode change that alters a dark-mode value. | Neutral text; keep dark tokens untouched. **Flag**, fail only when dark mode changed. | `light-mode-color-system`, owner rule 10-10. |
| **R6 — Modal-back contract** | One history guard entry per modal stack; a manual close never touches history. | A close handler that calls `history.back()` / `navigate(-1)`, or a modal that pushes more than one guard entry. | Close by state; let the guard pop on its own. | `modal-back-contract`, `pwa-back-history-state-index`. |
| **R7 — Positive claim, never inference from absence** | A capability, membership or status is gated on a positive tag/answer, never on the absence of one or on a guess that happens to work. | `if (!x)` deciding "unsupported"/"not a member" where `x` was simply never asked for; a wrong question read as "unreachable". | Ask directly; gate on the positive claim. | `positive-tag-even-when-guessing-works`, `wrong-question-not-unreachable`, `dead-control-is-usually-disabled`. |
| **R8 — Replaceable-event wipe rule** | A replaceable list (kind 3 follows, 10000 mutes, 10002 relays, 30xxx) is only ever published from a loaded base; an empty or filtered base is never published. | Publishing a kind-3/10000/10002/30xxx event whose list was built from a cache miss, a filter over a partial fetch, or an empty state. | Load the base (`loadFollowBase` pattern); refuse the publish when the base is unknown; never "replace with what I have". | `follow-list-wipe-footgun`, `replaceable-event-wipe-rule`. |
| **R9 — Honest status** | A spinner tracks the real operation; counts, activity and "done" come from answers, never fabricated; words say what happened, not what was asked. | A spinner ended before the operation resolves; a "Sent"/"Posted"/"Removed" said before the answer; a fabricated count or activity. | End the spinner on the real settle; report the answer ("Removed from 4 of 6 relays"). | `spinner-must-track-the-real-operation`, `discover-rubber-band`, honest-words review 10-10. |
| **R10 — Names and hooks without ESLint** | Icon-only buttons carry `aria-label`; hook dependency arrays are complete (no linter runs here). | **Flag** an icon-only `<Button>` without `aria-label`; **flag** a `useEffect`/`useCallback` using a value its deps omit. | Add the label; complete the deps or explain why not. | `client/src/lib/icon-button-names.test.ts`, `no-eslint-stale-hook-deps`. |
| **R11 — A harness must be able to fail** | A new test or rig is shown red once (sabotage or a known-bad input) before it is trusted; a test whose mock you wrote only proves you agree with yourself. | **Flag** a test added with no evidence it can fail; **flag** a test that asserts a mock's own return. | Prove red on main or with a one-line sabotage; test at a seam against a real answer where possible. | `CLAUDE.md` "Verify on the wire", the rigs in `ship/`. |
| **R12 — Just the rails** | Relay Outpost never custodies, routes or earns on users' money, and never runs or hosts the thing it is an interface for; it has no last word on content. | Code that holds, forwards or splits sats; a flow that only works through a relay we run; copy that promises moderation of the whole network. | Hand the action to the user's wallet/relay; say what we are. | `relay-outpost-is-just-the-rails`, `interface-not-host`. |

Rows R1, R2, R7, R8 are correctness; R3, R4, R5, R9 are the product's voice; R6, R10 are the app's contracts; R11 is method; R12 is principle.
